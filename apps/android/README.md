# Android приложение

«Дневник здоровья»: Android 10+, `io.github.voldemar64.healthapp`, русский интерфейс, только светлая тема. Версия 0.2.0 содержит ручной ввод давления и лекарств, график, календарь, отметки приёма и Room. Речь и уведомления ещё не подключены.

## Сборка и модули

| Инструмент | Версия |
| --- | --- |
| Temurin JDK | 21.0.13+9 |
| Gradle Wrapper | 8.13, SHA-256 в wrapper properties |
| AGP | 8.13.2 |
| Kotlin / Compose Compiler | 2.3.10 |
| Java / Kotlin target | 17 |
| min / compile / target SDK | 29 / 36 / 36 |
| SDK Build Tools | 35.0.0 |
| Room | 2.8.4 |
| KSP | 2.3.10 |

Версии библиотек находятся в `gradle/libs.versions.toml`. JDK запускает сборку; target 17 задаёт байткод и не добавляет отсутствующие Android API.

Lint считает предупреждения ошибками. Советы об обновлении фиксированных зависимостей и согласованного target SDK 36 имеют информационную важность: новый upstream-релиз сам по себе не ломает проверку bootstrap. Перед публикацией в магазине требования к target SDK проверяются отдельно.

`app` содержит Activity, Compose, ViewModel и тесты UI/хранения. `core/domain` — модели, проверки, статистика и расчёт повторов. `core/data` — Room, транзакции и сериализация точных доз. `HealthApplication` собирает зависимости; DI-фреймворк не нужен. `platform/speech` и `platform/reminders` остаются пустыми границами следующих этапов. Направления зависимостей прежние.

Зависимости зафиксированы: [Room](https://developer.android.com/jetpack/androidx/releases/room), [KSP 2.3.10](https://github.com/google/ksp/releases/tag/2.3.10). Схема Room v1 хранится в `core/data/schemas`; destructive fallback отсутствует. Bootstrap не содержал базы, поэтому его обновление не требует миграции. Для следующего изменения схемы нужны миграция и тест сохранения данных.

## Windows

PowerShell 7, команды из корня репозитория:

```powershell
# Скачать инструменты, проверить хеши, ознакомиться с SDK-лицензиями.
./scripts/setup-android.ps1
# Для уже прочитанных и принятых SDK-лицензий доступен -AcceptSdkLicenses.

# Выполнять в каждой новой сессии:
. ./scripts/android-env.ps1
./apps/android/gradlew.bat -p apps/android test lint assembleDebug
```

Инструменты, AVD и Gradle-кеш находятся в игнорируемом `.tooling`, архивы — в `.cache`. Скрипты меняют переменные только текущего процесса. Системные PATH и JDK остаются прежними. Android Studio для сборки не требуется.

Проверка ускорения и запуск эмулятора:

```powershell
. ./scripts/android-env.ps1
emulator -accel-check
emulator -avd health_api36 -memory 2048 -no-snapshot -gpu software
```

Команда запуска открывает окно эмулятора. Если ускорение недоступно, проверить виртуализацию в BIOS/UEFI и Windows Hypervisor Platform. Системные изменения и перезагрузка выполняются отдельно. Локальная проверка считается пройденной только после фактической загрузки устройства.

В другом PowerShell:

```powershell
. ./scripts/android-env.ps1
adb wait-for-device
./apps/android/gradlew.bat -p apps/android :app:connectedDebugAndroidTest
adb install -r ./apps/android/app/build/outputs/apk/debug/app-debug.apk
adb shell am start -n io.github.voldemar64.healthapp/.MainActivity
```

## Linux и CI

Нужны JDK 21, Android SDK и принятые лицензии. Указать `JAVA_HOME` и `ANDROID_HOME`, затем из этой директории:

```bash
sdkmanager 'platforms;android-36' 'build-tools;35.0.0'
./gradlew test lint assembleDebug
./gradlew :app:connectedDebugAndroidTest # при доступном устройстве
```

GitHub Actions выполняет JVM-тесты, lint и тесты устройств на API 29/36. `HealthRulesTest` проверяет числа, статистику, повторы, DST и ревизии. `StorageTest` проверяет настоящую Room-базу, повторное открытие файла, транзакции и уникальность отметок; `ManualEntryTest` — формы и действия пользователя; `BootstrapTest` — навигацию, светлую тему и масштаб текста. Для пустых платформенных библиотек допустим `NO-SOURCE`.

Инструментальные тесты используют отдельные `instrumentation-health.db` и `storage-test.db`. Запускайте `connectedDebugAndroidTest` на эмуляторе: Android Gradle Plugin устанавливает и удаляет тестируемое приложение. На телефоне с нужной историей используйте только обычный APK и ручной чек-лист.

Actions → успешный запуск → Artifacts: `health-app-debug` и отчёты доступны семь дней. APK подписан отладочным ключом. Ключи локальной среды и CI-запусков могут различаться: при конфликте подписей сначала удалить прежнюю тестовую установку. После появления пользовательских данных удаление приложения приведёт к их потере; стабильная подпись тестовых выпусков — отдельная задача.

## Проверка на телефоне

Скачать артефакт `health-app-debug`, распаковать APK и открыть на Android 10+. При необходимости разрешить установку выбранному файловому менеджеру. Альтернатива — USB debugging и `adb install -r`; при нескольких устройствах указывать `adb -s SERIAL`.

- Запуск показывает «Давление» и «Пока нет измерений».
- «Лекарства» открывает «Пока нет расписания»; повторные нажатия не дублируют экран.
- Back возвращает к давлению; следующий Back выполняет стандартное действие Android для корневой Activity.
- Поворот сохраняет вкладку. При большом шрифте содержимое доступно прокруткой, вкладки видны.
- При тёмной теме телефона стартовый экран и приложение остаются светлыми.
- TalkBack объявляет подписи и выбранную вкладку; декоративные иконки не дублируют текст.
- Нет запросов микрофона, уведомлений или сети.

Проверка ручного ввода:

1. Добавить 120/80, пульс 65, комментарий; проверить график и среднее. Добавить второе измерение, переключить 7/30 дней и произвольные даты.
2. Изменить запись, затем удалить с подтверждением. Ошибочное нижнее больше верхнего не должно сохраняться.
3. Создать лекарство с 0,5 таблетки в 09:00 и 1 таблеткой в 18:00. Проверить каждый день, затем дни недели (например, понедельник и четверг) и дату окончания.
4. Переключить сегодня/неделю/месяц, выбрать дату. Проверить отдельный приём и редактирование серии с будущей даты: прошлые названия и дозы остаются прежними.
5. Отметить «Принято» с фактическим временем, «Пропущено», отменить отметку. Повторные нажатия не создают дополнительные события.
6. Закрыть приложение, принудительно остановить и запустить снова; данные должны сохраниться. Повернуть телефон в незавершённой форме: поля должны остаться.
7. Проверить обе формы и календарь со шрифтом 200%, TalkBack и тёмной системной темой. На телефоне оценить удобство выбора даты и времени.

Расписание следует местному времени телефона, 09:00 остаётся 09:00 после поездки. Будущие индивидуальные изменения заменяются при изменении серии с выбранной даты; форма предупреждает об этом. Новые расписания начинаются сегодня или позже. Прошедший приём без отметки — «Не отмечено», не «Пропущено». График не ставит диагноз и не назначает лечение.

Физический телефон и TalkBack проверяются вручную; UI-тесты не заменяют оценку удобства чтения.

## Приватность

Медицинские записи находятся в приватной базе `health.db`. Manifest отключает backup, XML-правила исключают приватные области из облачного резервирования и переноса. Показатели, названия и комментарии не пишутся в технические логи. Дополнительного шифрования и экспорта пока нет. **Удаление приложения удаляет все записи**; при конфликте debug-подписи не удаляйте установку с нужной историей. Для обновления с сохранением данных используйте APK с тем же ключом и `adb install -r`.

Общие правила — в [архитектуре](../../docs/architecture.md).
