# Архитектура Health App

Дата: 2026-11-08. Реализованы пять модулей, ручной ввод, статистика, расписания и Room. Добавлены Vosk, системный TTS и подтверждаемый голосовой диалог. Напоминания остаются будущим этапом.

## Развёртывание и сервисы

Первая версия развёртывается как одно Android-приложение. База Room, речевая модель и бизнес-логика находятся на устройстве. Серверных сервисов и межсервисного HTTP нет.

Внутренние компоненты приложения:

| Компонент | Владелец | Ответственность |
| --- | --- | --- |
| HealthRepository | domain: контракт; data: RoomHealthRepository | Измерения, версии расписаний, исключения и отметки; согласованный Flow снимка |
| VoiceParser / VoiceDialog | domain | Текст в команду, черновик или запрос уточнения |
| VoiceInput / OfflineRecognizer | speech | Звук в промежуточный и окончательный текст |
| VoiceOutput / OfflineSpeechOutput | speech | Озвучивание подтверждения |
| ReminderScheduler | domain: контракт; reminders: реализация | Установка, отмена и восстановление сигналов |
| VoiceViewModel | app | Состояние голосового диалога и подтверждение |

Это Kotlin-компоненты, а не независимые процессы. Android `Service` не нужен для обычной короткой голосовой сессии в открытом приложении. Фоновое прослушивание потребует отдельного решения.

## Модули и зависимости

```text
:app
  ├── :core:domain
  ├── :core:data ────────────────→ :core:domain
  ├── :platform:speech ──────────→ :core:domain
  └── :platform:reminders ───────→ :core:domain
```

`app` собирает зависимости и управляет UI. `domain` содержит сущности, проверки, расчёт повторов, разбор команд, общие проверки и интерфейс репозитория. `data` хранит данные. `speech` и `reminders` изолируют Android и сторонние SDK. Направление стрелок означает зависимость при сборке.

Room — источник сохранённых пользовательских данных. Экраны подписываются на `Flow` репозиториев через ViewModel и получают `StateFlow` состояния. Временные черновики живут отдельно от сохранённых записей. Ручной и голосовой ввод используют одинаковые проверки и use cases.

Подход согласуется с рекомендациями Android по [модулям](https://developer.android.com/topic/modularization/patterns) и [локальному источнику данных](https://developer.android.com/topic/architecture/data-layer/offline-first).

## Данные и инварианты

| Сущность | Основные поля | Правило |
| --- | --- | --- |
| PressureMeasurement | id, systolic, diastolic, pulse?, measuredAt, recordedZoneId, note? | Пульс обязателен при записи; null и note сохранены для чтения старой истории |
| ScheduleRevision | id, seriesId, from, until?, draft | Интервал действия ревизии; название, повтор, даты и несколько DoseTime в draft |
| DoseTime | id, time, dose | Устойчивый идентификатор слота, местное время, точная доза |
| Occurrence | seriesId, revisionId, slotId, date, time, name, dose | Вычисленное событие или сохранённое исключение одного дня |
| IntakeRecord | occurrence, plannedAt, recordedZoneId, status, takenAt? | Снимок имени, дозы и времени на момент отметки |

`Dose` хранит точное десятичное значение и единицу `TABLET`, `MG` или `G`. В Room значение сериализуется без потерь, например десятичной строкой. `Float`/`Double` для дозы не использовать. Количество таблеток не переводится в массу без явно заданного соответствия.

Повторы: `ONCE`, `DAILY`, `WEEKLY` с набором дней недели. Просмотр месяца не означает ежемесячный повтор. Будущие события вычисляются для выбранного интервала; бесконечный ряд записей заранее не создаётся. Названия повторно выбираются из ревизий; отдельный каталог голосовых псевдонимов пока не нужен.

Измерение и факт приёма хранятся как `Instant`. Расписание следует местной зоне телефона: 09:00 остаётся 09:00 при поездке. Факт фиксирует плановый Instant и zoneId; последующее изменение зоны не переписывает историю.

При переходе летнего времени несуществующее время сдвигается на длину пропуска, повторяющееся время рассчитывается один раз по более раннему смещению. Политика централизована в Occurrence.instant и покрывается тестами.

При изменении серии прошлые события и отметки сохраняются. Новые события получают новую ревизию. `occurrenceKey = seriesId/date/slotId` стабилен между ревизиями; primary key в таблице intakes защищает от повторной отметки. Изменение сегодня действует с текущего момента, в будущем — с начала выбранного дня. Уже прошедший слот сегодня не дублируется при переносе на вечер. Отмена отметки сохраняет снимок в исключении; изменение серии заменяет только будущие исключения с выбранной даты.

HealthApplication создаёт одну базу и репозиторий без DI-фреймворка. Room invalidation запускает чтение четырёх таблиц в транзакции; UI не получает частично изменённую серию. Черновики Compose rememberSaveable восстанавливаются при пересоздании Activity. Схема Room v1 экспортируется в Git, destructive migration не включена. База содержит все записи в одном снимке; пагинация и SQL-агрегации понадобятся при больших объёмах истории.

## Поток голосового ввода

```text
Запуск пользователем → разрешение микрофона → загрузка локальной модели
→ окончательный текст → VoiceParser / VoiceDialog → черновик / уточнение
→ заполнение видимой формы и короткое подтверждение «да / нет / исправить»
→ общий use case → Room → обновление UI
```

Промежуточный текст не выполняет команды и не выводится; окончательные значения заполняют общую форму. Навигация может выполняться сразу; добавление измерения/расписания требует «да»; однозначная отметка сегодняшнего приёма выполняется сразу. Изменение и удаление существующих данных голосом недоступны. Неполная команда не получает выдуманные название, дозу или время.

Состояния диалога: COMMAND, FIELD, CONFIRM, CORRECTION, CHOICE, COMMIT, PAUSED, CANCELLED, NAVIGATE, READ; UI отдельно показывает подготовку, озвучивание, прослушивание, паузу и ошибку. Отмена очищает черновик. Уход приложения в фон завершает запись; возвращение не возобновляет микрофон автоматически. Повторное подтверждение не должно приводить к второй записи.

Названия сопоставляются с личным списком лекарств. Неоднозначные совпадения дают выбор. Новое название показывается для подтверждения, неизвестное слово не заменяется молча похожим. Правильность распознанных значений проверяет пользователь при подтверждении.

Во время озвучивания микрофон приостановлен, чтобы приложение не распознало собственный ответ. Для следующего ответа пользователя начинается новая фаза прослушивания в рамках открытой сессии.

## Речевые адаптеры и поставка

`VoiceInput` и `VoiceOutput` находятся в `platform/speech`, публичные методы используют только Kotlin-типы. `VoiceInput.prepare/listen(context, onPartial)/release` загружает модель, возвращает окончательный текст и сообщает partial через callback. Отмена coroutine прекращает AudioRecord в finally. `VoiceOutput.prepare/speak/stop/release` использует Android TTS с установленным русским голосом, у которого `isNetworkConnectionRequired == false`. Отсутствие голоса — явная ошибка с переходом в настройки.

`VoiceDialog` в domain — чистая машина состояний без IO. Вход содержит текст, текущие данные, Instant и ZoneId. Только точное подтверждение формы или однозначная команда сегодняшнего приёма переводит состояние в COMMIT. `VoiceViewModel` последовательно озвучивает, слушает и выполняет подтверждённую запись через HealthRepository. Во время озвучки микрофон отсутствует. После подтверждения одна операция записи завершается даже при остановке Activity; повторный callback не запускает её снова. При ошибке записи автоматического повтора нет.

Vosk 0.3.75 и JNA 5.18.1 зафиксированы в version catalog. `prepareSpeechModel` автоматически скачивает официальный архив в кеш сборочной машины, проверяет ожидаемый SHA-256, безопасно распаковывает assets и создаёт manifest хешей файлов. На телефоне проверенные файлы копируются через временный каталог в noBackupFilesDir; готовность отмечается после переименования. Модель обновляется с APK. В Git хранятся исходники, метаданные и лицензии; веса остаются вне Git. Подробности — в [карточке модели](../models/vosk-ru/README.md).

Модель распознавания встроена, голос синтеза — системный. Поэтому полностью автономный диалог на чистой установке возможен только при уже установленном русском офлайн-голосе Android. В APK нет INTERNET permission и сетевого fallback. Настройки стороннего системного TTS управляются Android.

Голосовой прототип поддерживает одну дозу для нескольких времён, относительные даты и ручную коррекцию неизвестного названия. Разные дозы и сложные даты задаются обычной формой. Обе формы используют общий VoiceDraft с сохранением через SavedStateHandle, включая отдельные дозы каждого слота; возвращение на экран не включает микрофон автоматически.

## Расписание и напоминания

Календарь — данные и расчёт повторов. Напоминания — необязательный побочный эффект после сохранения расписания; отказ разрешения не отменяет запись расписания.

При изменении расписания транзакция Room сохраняет данные и признак необходимости пересчёта сигналов. Планировщик применяет изменения идемпотентно и подтверждает обработанную ревизию. При новой ревизии во время обработки пересчёт остаётся необходимым. Это закрывает окно сбоя между сохранением данных и вызовом AlarmManager.

Для точного времени планировать ближайшее одноразовое событие каждого активного расписания, затем следующее. Идентичность `PendingIntent` определяется расписанием; отмена и замена устойчивы к повторному вызову. Получатель проверяет актуальную ревизию перед уведомлением. Просроченный сигнал не означает, что лекарство принято.

Пересчёт выполняется после изменения расписания, запуска приложения, перезагрузки, обновления приложения, изменения системного времени и восстановления доступа к точным сигналам. Принудительная остановка приложения и отключённые уведомления требуют отдельной обработки в UI.

WorkManager подходит для отложенного восстановления согласованности, но не задаёт точное время приёма. Для AlarmManager проверять доступ к точным сигналам; при его отсутствии явно показывать состояние напоминаний. Подробности ограничений: [Android alarms](https://developer.android.com/develop/background-work/services/alarms) и [разрешение уведомлений](https://developer.android.com/develop/ui/compose/notifications/notification-permission).

## Данные и приватность

Аудио по умолчанию обрабатывается в памяти и не сохраняется. Транскрипты, названия препаратов и показатели не пишутся в технические логи. База находится в приватном хранилище приложения. Room сам по себе не означает шифрование базы.

Для первой версии исключить медицинскую базу и черновики из автоматического облачного backup; модель тоже не резервировать. Экспорт, перенос данных и дополнительное шифрование требуют отдельного решения. Удаление приложения без экспорта означает потерю локальных записей — это нужно объяснить пользователю.

## Проверка архитектуры

- JVM: числа, дроби, единицы, незавершённые и неоднозначные команды; календарь, DST, конец месяца, ревизии.
- Room: миграции, транзакции, уникальность отметок, точное хранение дозы, запросы статистики.
- UI: одинаковое сохранение ручного и голосового черновика, отмена, подтверждение и ошибки.
- Устройство: авиарежим с первого запуска, отзыв разрешения микрофона, прерывание сессии, повреждённая модель, память и задержка.
- Напоминания: перезагрузка, отказ разрешений, редактирование серии, двойная доставка и устаревший сигнал.

Ключевая метрика речи — точность всей записи: название, количество, единица, время и повтор. Отдельно измерять задержку и память на слабом устройстве. Порог выпуска утверждается после первого замера; текущая архитектура не обещает конкретную точность.

## Упрощённый интерфейс и отчёт (2026-11-11)

Давление показывает 7/30 дней включительно с сегодняшним, графики и историю. Статистика перенесена в PDF. Календарь лекарств — неделя из семи дат или месячная сетка с понедельника; карточки всех лекарств доступны через бургер. Изменение серии/будущего приёма и отмена сегодняшней отметки доступны в подробностях.

`markTakenNow` внутри транзакции получает clock.instant(), проверяет местную сегодняшнюю дату и актуальность occurrence. Уже принятый приём не переписывается. `unmarkToday` разрешает отмену только сегодняшней записи, сохраняя снимок в исключении. Старые mark/unmark и SKIPPED остаются совместимыми для истории; UI и голос не создают новые пропуски. Схема Room v1 не менялась.

SpeechContext выбирает грамматику ожидаемого короткого ответа; FREE используется для названий/полных фраз, `[unk]` не исполняется как команда. TTS и AudioRecord не работают одновременно. «Нет» переводит диалог в PAUSED; подтверждённая запись завершается вне отмены и сообщает успех даже при уходе в фон. Ручные правки во время COMMIT запрещены.

PDF: ReportSnapshot фиксирует HealthData, период, Instant и ZoneId до выбора файла. PdfDocument строится вне главного потока; Android SAF получает application/pdf без разрешения на весь диск. ChartData используется экраном и PDF. Таблица учитывает снимки фактов, старые SKIPPED, неотмеченные и ещё будущие приёмы; заголовок повторяется на каждой странице таблицы. Длинные строки переносятся, страницы нумеруются. Сохранение не меняет базу.
