# Релизы Android после зелёного CI

Автоматическая подготовка пока **не включена**: текущая GitHub-авторизация не имеет права `workflow`, расширение прав отклонено владельцем. Готовый патч [android-release-automation.patch](android-release-automation.patch) можно применить позже командой `git apply docs/android-release-automation.patch` и отправить через авторизацию с разрешением менять workflow. Сейчас работает локальная публикация после существующего зелёного CI; команды ниже применимы без патча.

После применения патча workflow `.github/workflows/android.yml` автоматически готовит черновик GitHub Release после успешных `build` и всей матрицы `device-tests` (API 29 и 36). Только push в `main` или ручной Android workflow на `main`; PR ничего не публикует. Ключ подписи остаётся локально и не передаётся GitHub. Поэтому окончательная публикация требует локальной команды владельца.

## Следующая версия

1. Повысить `versionName` (MAJOR.MINOR.PATCH) и `versionCode` в `apps/android/app/build.gradle.kts`.
2. Открыть PR, дождаться проверок и объединить в `main`.
3. Дождаться полностью зелёного Android workflow на итоговом коммите main. После включения автоматизации задача `Prepare Android release draft` создаст черновик `v<versionName>` с описанием и ссылкой на CI.
4. В корне репозитория выполнить локально (PowerShell; заменить RUN_ID на номер этого запуска):

```powershell
. ./scripts/android-env.ps1
python .github/scripts/release_android.py --run-id RUN_ID --keystore .tooling/android-user/debug.keystore --input .tooling/release-RUN_ID-input --output .tooling/release-RUN_ID-output --certificate .github/android-signing-cert.sha256
```

Нужны `gh auth login`, Python 3.11+ и Android build-tools 35.0.0. Входной каталог должен отсутствовать: скрипт скачивает свежий APK из указанного CI run. При повторе выбрать новый входной каталог. Артефакты CI хранятся 7 дней; при истечении срока повторно запустить исходный workflow.

## Проверки и подпись

Локальная команда проверяет GitHub: Android workflow завершён успешно на main, сборка, обе версии эмулятора успешны. APK скачивается из этого же run, метаданные читаются из него через aapt, без локальной пересборки. Проверяются обычный applicationId, debug-вариант, один универсальный APK и версия. Пакет `.qa` выпускать нельзя.

APK подписывается существующим локальным ключом прототипа. Сертификат сверяется с публичным отпечатком `.github/android-signing-cert.sha256`, проверенным по опубликованной v0.3.0. Это сохраняет обновление предыдущих опубликованных версий без удаления истории. Формат остаётся debug/prerelease; production-подпись — отдельная задача.

Приватный keystore не коммитится, не загружается в GitHub и не включается в артефакты. Пароль/alias стандартные для существующего debug-keystore; секрет — сам закрытый ключ. Сохранить резервную копию ключа отдельно от кешей сборки.

После загрузки APK и SHA256SUMS.txt сверяются размеры и серверные SHA-256. Только после проверки черновик становится публичным prerelease. Неполная загрузка оставляет черновик. Опубликованные релизы неизменяемы: push с прежней версией пропускает выпуск. Для исправлений повышать обе версии.

Черновик разрешено продолжать только для того же SHA; чужой тег не переносится. Main workflow не отменяется новым push посреди подготовки. В подготовленном патче права записи выданы только задаче подготовки черновика; ключей подписи в Actions нет.

Проверка логики: `python -m unittest discover -s .github/scripts -p 'test_*.py' -v`. Тесты используют искусственные данные, без GitHub и настоящего ключа.
