| 7. Голос и доступность | Выбор профиля, «Эйэнди» при активном прослушивании, подтверждение записи, команды приёма/запаса/таймера; «Сегодня», «История», «Лекарства», настройки и справка | 30 письменных фраз и 7 речевых инструментальных тестов прошли; два живых участника, TalkBack на телефоне ожидаются |

Периодный `observeProfile(id,start,end)` фильтрует давление, схемы, исключения и приёмы в Room; экран давления и PDF его используют. Остальные экраны и голос вызывают `observeProfile(id)` с явным профилем; старый `data` остаётся только для совместимости тестов. Карточки и журнал остатков загружаются по профилю. Ограниченные запросы для календаря и сводки напоминаний остаются улучшением производительности, как и дальнейшее разделение экранного ViewModel. Поля уже созданной личной карточки пока не редактируются; новая карточка, схема и разовое напоминание доступны экраном. Голос принимает «через…» и «сегодня/завтра в HH:MM» с подтверждением.

## Приёмка, требующая устройства

API 36 прогон завершён. Эмулятор создавал снимок памяти 2,68 ГБ и мог исчерпать диск; после завершения тестов тестовый AVD закрыт, снимок удалён. Проверка API 29 локально не выполнялась: образ API 29 в этой среде отсутствует. Установка поверх предыдущего APK с настоящей заполненной `health.db` не выполнялась, чтобы не трогать пользовательское устройство и данные.

Перед выдачей заказчику завершить матрицу на API 29, установить APK поверх прошлой версии с заполненной `health.db`, затем проверить на физическом телефоне: точность напоминаний в пределах минуты в согласованных условиях и режиме простоя, перезагрузку/полночь/смену зоны, отзыв разрешений, заблокированный экран, TTS и голос двух участников по [корпусу](voice-corpus.md). Измерить ≥90% завершений не более чем с одним уточнением и ноль записей без подтверждения. Пройти TalkBack, 200% шрифт, контраст и области нажатия. До этих проверок APK считать тестовым, не принятой версией Andy v1.

## Слабые места и следующие улучшения

1. Перевести календарь и голос с полного профильного снимка на запросы с периодом; разделить экранный ViewModel по сценариям. Это снизит стоимость длительной истории и сверки напоминаний.
2. Добавить редактирование личной карточки с явной политикой изменения единицы и имени при существующих схемах; не конвертировать мг/г автоматически.
3. Провести API 29 и системные тесты напоминаний на физическом телефоне; обеспечить свободное место для снимков эмулятора в CI.
4. После полевого голосового теста расширить варианты дат и времени, словарь произношений и неоднозначные названия по фактическим ошибкам.
